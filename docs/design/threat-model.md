# PhoneBridge threat model

## Scope and trust boundaries

Protect documents, clipboard text, file contents, video, pairing identity, and session availability. Trust the browser and operating system on each device, the PhoneBridge frontend delivered over HTTPS, and the laptop display used to show the QR. Treat the network, relayed signaling, and all received peer data as untrusted. A device or frontend already under an attacker’s control can read content that device can access.

The room token grants temporary entry to signaling. The QR fragment carries the laptop fingerprint outside the HTTP request. SDP and candidate negotiation necessarily disclose connection metadata to the participants and signaling infrastructure. User content travels through WebRTC after negotiation. TURN relays encrypted packets and can observe traffic metadata. [RFC 8827 WebRTC security architecture](https://www.rfc-editor.org/rfc/rfc8827.html)

## Risks and required controls

| Risk                                      | Required mitigation                                                                                                                                                                                                                                                               | Verification                                                                |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Wrong remote peer or altered signaling    | Pin the QR’s SHA-256 fingerprint before setting the laptop remote description. Compare the effective fingerprint for every negotiated section in scope, including inherited defaults. Stop on a missing or ambiguous pin. Both devices display SAS digits for a human comparison. | T06 pairing tests for a mismatched pin and real-device verification in T07. |
| Unauthorized room entry                   | Use a random 128-bit token, one host and one phone, short unjoined expiry, and immediate invalidation on peer close. Keep tokens out of logs and avoid third-party referrers or scripts carrying pairing URLs.                                                                    | T05 room tests and T15 security review.                                     |
| Malformed or oversized peer messages      | Validate schema, version, channel, sender, bounds, and transfer state before application handling. Enforce transfer limits and backpressure, release buffers on cancel or close, and avoid replying to an incompatible peer’s error.                                              | Protocol tests in T04, transfer tests in T13, and review in T15.            |
| Untrusted names or clipboard text         | Render received text as text. Sanitize file names for display and download, and offer an explicit clipboard fallback when focus or permissions block writing.                                                                                                                     | Clipboard and file tests in T13–T15.                                        |
| Incorrect or incomplete file data         | Track chunk bounds and completeness per transfer. Check SHA-256 before treating received bytes as complete.                                                                                                                                                                       | Transfer round-trip and cancellation tests in T13.                          |
| Unexpected camera or motion collection    | Ask for permission through a clear user action, show the active feature, and stop capture when the mode or session ends. Exclude test sensor hooks from production.                                                                                                               | Pairing and camera tests, real-device checks, and review in T28.            |
| Data retained by signaling or diagnostics | Relay setup frames without persisting their contents or logging them. Keep room metadata limited to role, expiry, and connection bookkeeping. Keep SDP, candidates, room credentials, and user content out of copied diagnostics.                                                 | T05 teardown tests and T15 review.                                          |

## Residual risk

A person who can see or copy the QR can attempt to join during the room’s lifetime. The short SAS is a human comparison aid. A peer who accepts a file or clipboard transfer can retain that content. TLS and fingerprint checking depend on a trustworthy browser and delivery origin. T15 covers the first live implementation and T28 reviews the final feature set.
